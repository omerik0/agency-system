## מטרת הפרויקט
לימוד מעמיק של עבודה עם סוכני AI (Claude Code) לבניית מערכת שמנהלת עבור עסק אמיתי: קליטת פרויקט מלקוח → בניית אתר → פריסה → סליקה. הפרויקט ישמש גם לעסק בפועל וגם כפרויקט רזומה.

## סדר עבודה (סוכן הלידים נדחה לשלב מאוחר יותר)

### שלב 0 — תשתית
- תיקיית פרויקט אחת ב-VS Code על ה-Mac mini: `agents/`, `sites/`, `db/`, `infra/`
- Claude Code כבר מותקן ורץ (טרמינל). תוסף VS Code הוא אופציונלי — נותן diff view נוח בתוך העורך, לא כלי נפרד.
- DB ראשי (business DB) — Supabase או Neon (Postgres מנוהל, טיר חינמי בהתחלה)

### שלב 1 — סוכן בניית אתרים
- קלט: בריף פרויקט (שם עסק, תוכן, מיתוג, סוג עמוד)
- פלט: דף נחיתה סטטי (HTML/Tailwind) → בהמשך אתר מלא (Next.js) לפי הצורך
- עובד מתוך template בסיס שמשתפר עם הזמן, לא כותב מאפס כל פעם

### שלב 2 — סוכן סליקה ופריסה
- פריסה: Vercel/Netlify לדפי נחיתה סטטיים, Docker/VPS (Hetzner/DigitalOcean) לאתרים עם backend
- סליקה: חיבור לחשבון Stripe/Tranzila **של הלקוח עצמו** — לא של, ולא דרך, החשבון שלך
- כל אתר מקבל רשומה ב-DB הראשי עם סטטוס (בבנייה/פעיל/דורש טיפול)

### שלב 3 — האורקסטרטור
- Agent אחד ב-Claude Code שמנהל את הזרימה: פרויקט חדש → קריאה לסוכן בניית אתר → אישור שלך → קריאה לסוכן פריסה/סליקה → עדכון DB
- נבנה כ-subagents בתוך Claude Code (יש תמיכה מובנית להגדרת תפקידים נפרדים)

### שלב 4 (מאוחר יותר) — סוכן מחקר לידים
- Meta Graph API, endpoint "Business Discovery" — שליפת נתונים ציבוריים לגיטימית של עסקים אחרים לפי username, ללא scraping

## ארכיטקטת מסדי הנתונים — ההבחנה החשובה ביותר

### DB #1 — "משרד העסק" (שלך, אחד בלבד)
מנהל את **העסק שלך**. טבלאות בסיס:
- `clients` — פרטי לקוחות, איש קשר
- `projects` — סטטוס כל פרויקט אתר, תאריכים
- `invoices` — כמה כל לקוח חייב **לך**, על מה (בנייה / אחזקה חודשית), מתי שולם
- `deployments` — איפה כל אתר פרוס, מתי עודכן לאחרונה

זהו הדאטהבייס שאתה מסתכל עליו כדי לנהל את העסק. אחד בלבד, לא לכל לקוח.

### DB #2 — "העסק של הלקוח" (אחד לכל לקוח, רק אם צריך)
רלוונטי **רק** אם לאתר יש פונקציונליות דינמית (חנות, הזמנות, משתמשים רשומים). מכיל את **הנתונים העסקיים של הלקוח עצמו** — מוצרים, הזמנות, לקוחות שלהם. דף נחיתה פשוט לא צריך את זה בכלל.

### מודל תשלומים מומלץ (הכי פשוט לניהול)
- אתה מארח הכל (גם DB #2 של הלקוחות) תחת החשבונות שלך — לא מנהלים חשבון הוסטינג נפרד לכל לקוח.
- אתה גובה מהלקוח: **דמי בנייה חד-פעמיים + דמי אחזקה/הוסטינג חודשיים קבועים**.
- הסליקה בפועל (תשלומים מלקוחות-של-הלקוח) עוברת ל**חשבון הסליקה של הלקוח עצמו** — לא נוגעת בכסף שלך, ולא עוברת דרכך.

## הערה חשובה — סוכן איתור לידים
Scraping אגרסיבי של אינסטגרם מפר את תנאי השימוש וחשוף לחסימות. כשנחזור לזה, נשתמש ב-Meta Graph API הרשמי עם endpoint Business Discovery, הפועל דרך חשבון עסקי מאושר.
